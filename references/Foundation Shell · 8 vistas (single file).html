Foundation Shell · Chrome de navegación

Dos shells canónicos. /ops con 12 módulos para todos los roles (royal como acento). /admin con 10 módulos solo para Admin (info como acento, header "PANEL ADMINISTRATIVO" + filete royal en borde derecho). El header de página, búsqueda Cmd+K y mecanismo de alternancia son los mismos en ambos shells.

Decisión sobre /admin: combinación A + C

Adopto las dos. (C) Header "PANEL ADMINISTRATIVO" con dot pulsante info da certeza textual inmediata sin ambigüedad — un Admin que vuelve después de horas no necesita inferir el contexto. (A) Background n-975 + filete 1 px royal en borde derecho añade la señal cromática "área privilegiada" sin invadir contenido. La combinación las refuerza mutuamente: el header captura la atención cognitiva, el filete trabaja en visión periférica. El active state pasa de royal a info-500 para una tercera capa de diferenciación.

✓Validación · 6 puntos críticos
✓
Shells inmediatamente distinguibles — combinación A+C: header textual "PANEL ADMINISTRATIVO" con dot pulsante info, fondo n-975 (más oscuro que n-950 de ops), filete royal 1 px en borde derecho, logo con bg info-d, active state en info-500. Cuatro señales redundantes garantizan reconocimiento instantáneo.
✓
Alternancia visible no agresiva — botón "Panel Admin" outline con tinte info / "Volver a Operaciones" outline neutro. Ambos en altura 32 px, antes del avatar. No compiten con CTAs primarios; se sienten contextuales como "Switch project" en Linear.
✓
5 secciones agrupadas no abrumadoras — Catálogo y stock (2), Operación comercial (4), Bodega y movimiento (3), Taller (2), Soporte (1). Headers de sección en mono caps n-500 sirven como ancla, no como ruido. La operación comercial es la sección más densa porque concentra el día a día del Vendedor.
✓
Header como Linear / Vercel — search 320 px en fondo n-50 con borde sutil, atajo ⌘K visible, abre modal completo con agrupación contextual y atajos de teclado tipo "G I" (go to Inventario). El chip de sede como indicador de contexto, no como CTA. Avatar al final como dropdown denso con switcher de sedes.
✓
Coherencia desktop → tablet → mobile — el border-left de 2 px del active state se conserva en rail tablet, los iconos crecen de 16 a 18 px, los headers de sección desaparecen. En mobile, el active state migra al bottom tab (color p-600) o al item del drawer. La identidad del shell se mantiene en cada breakpoint.
✓
Mobile prioriza acción frecuente — para rol Vendedor, el FAB Vender es la acción del día. Para Bodeguero, sería "Recibir" o "Picking". Para Técnico, "Iniciar OT". El bottom tab es configurable por rol; las otras 4 entradas son shortcuts a los módulos más visitados, con "Más" abriendo el resto en drawer.
